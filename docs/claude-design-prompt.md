# Elmanhg — High-fidelity, fully functional build for Claude Design

You are building the production-quality front end of **Elmanhg (المنهج)**, an Arabic-first exam-prep platform for Egyptian Thanaweya Amma students. This package contains a working wireframe prototype and a finished design system. Your job is to rebuild the wireframe as a polished, fully interactive product using the design system exactly. Do not invent new flows, screens or business rules. Do not change the wording of any Arabic copy unless it is obviously a typo.

## 0. What is in this package

| Path | What it is | How to use it |
|---|---|---|
| `prototype/index.html`, `prototype/app.js`, `prototype/data.js`, `prototype/styles.css` | The working wireframe. Vanilla JS, hash router, localStorage state, seed data, real graders, all three roles. | This is the **functional spec**. Open the prototype first: serve the `prototype/` folder with any static server and open `index.html`. Switch role and user from the top bar. Reset data with the button.

## 1. Deliverable

A single self-contained web app that runs from a static folder with no build step and no backend:

- `index.html`, one CSS file, one or more JS files, seed data. No frameworks that require a bundler. Plain HTML/CSS/JS, or React via a single UMD script tag if you prefer, but the output must open by double-clicking `index.html` or serving the folder.
- Fonts self-hosted or via Google Fonts `<link>`: **Poppins** (400, 700, 800) for Latin and **Almarai** (400, 700, 800) for Arabic, stack `'Poppins', 'Almarai', Tahoma, sans-serif`.
- All state in `localStorage` under one key, with a working "إعادة ضبط البيانات" (reset) button, exactly like the prototype.
- Hash router. Every route listed in section 4 exists. Browser back and forward work.
- Every button, link, tab, option, input and form in the prototype works in your build. Nothing is decorative. If the prototype does something on click, yours does the same thing.
- `lang="ar"` and `dir="rtl"` on `<html>`. Logical CSS properties only. No left/right margins or paddings.
- Responsive: designed first at **375 px** width, verified at 390, 768 and 1280. No horizontal page scroll at any width. Tables scroll inside their card on mobile.
- No console errors. No emoji in UI. No dark mode.

## 2. The design system (canonical file: `docs/design-system.md`)

### 2.1 Colours

Define these as CSS variables on `:root` and use nothing else.

```css
--bg: #F2F7FD;            /* canvas mist: page ground */
--surface: #FFFFFF;       /* cards, sheets, inputs, app bar, tab bar */
--soft: #ECF2FA;          /* muted chips, pending and role badges, progress track, secondary and ghost hover, user bubbles */
--text: #252B2F;          /* charcoal: primary text; never a fill */
--text-2: #666E7E;        /* slate: captions, labels, meta, inactive tab bar */
--border: #E6ECF2;        /* hairline on cards, rows, dividers, tab bar */
--border-strong: #D6DEE6; /* steel: inputs, selects, option outlines, inactive pill tabs */
--accent: #116EEE;        /* Signal Blue: logo, secondary/selected/active borders, focus ring, progress fill, chart bars; never a filled action, never body-size text except the logo */
--accent-text: #0E64DA;   /* Signal Blue text shade: links, secondary and active labels, chips, circle tiles */
--accent-soft: #EAF2FE;   /* active nav and pill tab fill, selected option fill, toggled secondary, accent chips */
--action: #11EE92;        /* Spring Mint: primary button fill only, one per screen */
--action-hover: #0FD683;  --action-pressed: #0DBF75; /* hover and pressed on the primary button */
--ok: #16A34A;      --ok-soft: #E6F6EB;       /* non-text only: borders, icons, pass fill (status exception) */
--ok-text: #166534;                           /* success text, ok badge text, verdict icon */
--bad: #C8233A;     --bad-soft: #FEF1F2;      /* wrong, rejected, overdue, destructive (status exception) */
--warn: #B45309;    --warn-soft: #FEF3E2;     /* partial credit, pending review (status exception) */
--v2: #6A3FB5;                                /* "v2" badge only */
--hero: linear-gradient(90deg, #3B1E90 0%, #5A3CC4 30%, #3A6EF0 100%); /* landing hero, student home banner, student progress summary, subscribe header ONLY; mirrored (270deg) in RTL */
```

Colour rules:
- Mint = the one primary action per screen, in every tab and every filtered or empty state (a modal dialog is its own screen). Filter-form «تطبيق», actions repeated per card or row, inline add/rename forms and the Home plan line's «اشترك» are outline; a no-results «مسح الفلاتر» is outline when the screen already has its mint («دعوة» on the users page). Signal Blue = brand, link, current place, selection, focus, progress, charts. Green/red/amber = status (documented exception). Nothing else is coloured.
- Status text uses `--ok-text`, `--bad` or `--warn` on white or its soft background. `--ok` itself is never text. Badges are soft fills; no white text on green.
- The hero gradient appears only on the landing hero, the student home banner, the student progress summary (the same headline banner as Home) and the subscribe header; never on lesson, quiz, exam, teacher or admin screens. White text keeps ≥ 20 px from the gradient's end edge.
- Charcoal is never a fill. Signal Blue is never a filled action. Mint is only the primary button fill.
- Lesson content areas are pure white with no tint.

### 2.3 Spacing, radius, elevation

- Base unit 4 px. Scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64 (landing section gap).
- Page gutter 16 px mobile, 24 px desktop. Content max width 1200 px, centred.
- Card padding 16 px mobile, 20 px desktop. Gap between stacked cards 12 px. Gap between cards in a grid 12 px.
- Section spacing: 24 px between an H2 and the previous block, 12 px between H2 and its content.
- Radius: `--r-sm` 5 px inputs, selects, textareas; `--r-md` 16 px options, list items, menus, bubbles; `--r-lg` 16 px cards, sheets, dialogs, hero banners; `--r-pill` 45 px buttons, badges, tabs, chips; circles (9999 px) for subject, unit and icon tiles.
- One shadow: `--shadow-1: rgba(0,0,0,.1) 0 1px 2px 0` on cards, tiles, the app bar, menus, dialogs, sheets, toasts and the assistant button. No other elevation.
- Cards: white, hairline border, shadow-1. No coloured left or right borders ever.

### 2.4 Components and their states

**Buttons.** Pill shape (45 px radius), 44 px min height (36 px for the `sm` size used by table row actions in every table, student and admin: a documented exception to the 44 px rule, because rows are dense; adjacent actions keep adequate spacing per WCAG 2.5.8), label 14 px weight 700, horizontal padding 20 px (12 px for sm). Disabled 45 percent opacity. Focus ring 2 px `--accent` offset 2 px. The primary is the mint pill with a charcoal label: hover `--action-hover`, pressed `--action-pressed`. Secondary and ghost hover to `--soft`. Transition 150 ms. One mint button per screen; an action repeated per card or row (subscribe on each plan card) is secondary.

| Variant | Fill | Text | Border | Where |
|---|---|---|---|---|
| Primary | `--action` | `--text` | none | One per screen: start quiz, check answer, submit exam, save, sign up |
| Secondary | transparent | `--accent-text` | 2 px `--accent` | Everything else, including subscribe and Ask a Teacher per card |
| Danger | transparent (hover `--bad-soft`) | `--bad` | 2 px `--bad` | Reject, delete, cancel subscription, fail payment |
| Ghost | none | `--text` | none | Tertiary inline actions, sign-out (table row actions are secondary or danger `sm`) |

Every enabled button, select and `[role=button]` shows the pointer cursor; disabled controls show not-allowed. Row actions in every table are `sm` buttons (36 px): secondary for neutral actions, danger for destructive ones (same outline, red text); a row link is a secondary `sm` button.

**Quiz option.** Full-width `<label>` containing the input, 48 px min height, `--r-md` (16 px), 16 px, 12 px vertical and 14 px horizontal padding, 10 px gap between control and text, 8 px gap between options. States: default white with the steel `--border-strong`; hover `--soft`; selected `--accent-soft` fill with `--accent` border; after check, correct `--ok-soft` with `--ok` border and wrong `--bad-soft` with `--bad` border. Radio and checkbox controls 18 px with `accent-color: var(--accent)`. The same option card is used for choice groups outside the quiz (multi-unit exam units and sizes); a disabled option has 45 percent opacity and no hover fill, and a caption line may sit under the label.

**Feedback panel** (under the question after checking): `--r-md`, 12 px by 14 px padding, soft background and strong border in the verdict colour, a 26 px filled circle icon (check or x) at the start, bold verdict, explanation in `--text-2`.

**Badges.** Pill, 12 px 700, 2 px by 10 px padding. `ok` `--ok-soft` fill with `--ok-text` text; `bad` `--bad-soft` fill with `--bad` text; `pending` `--soft` fill `--text-2` text; `role` `--soft` fill `--text` text; `v2` transparent with `--v2` outline and text.

**Progress.** Track `--soft`, fill `--accent` for mastery and `--ok` for a passed exam. 6 px tall, fully rounded. The headline counter is the student home hero banner (on `--hero`, 12 px between rows; the same banner tops `#/student/progress`): the counter sentence in white 800 at H1 size below 900 px and Display from 900 px, a 6 px mastered-share bar in white on a 30 % white track, then three stat chips (seen, mastered, day streak): white pills with a caption label in `--text-2` and a 700 value in `--text`. It has no button; the next-lesson card keeps the one mint action.

**Navigation.** App bar: one row, 56 px tall, sticky, white with the one subtle shadow (no bottom border), inside the same 1200 px container as the page: logo (Signal Blue `--accent`, 18 / 24 px 700, links home) · nav · role badge · display name · sign-out (ghost). Mobile: bottom tab bar, white, hairline top border, at most 4 items, Lucide stroke icons 22 px at 1.8 px stroke, label 12 px (micro), active `--accent-text` 700 with the icon on an `--accent-soft` pill, inactive `--text-2`, bottom padding for the device safe area. A role with more than 3 destinations shows its 3 primary destinations plus a fourth item "المزيد" that opens a list of the rest. Desktop (≥ 900 px): the nav sits inline in the app bar as 36 px pills, inactive charcoal `--text` 14 px 700, hover `--soft`, active `--accent-soft` fill with `--accent-text`; the display name and the sign-out label show from 1200 px (below that sign-out is icon only). The admin shows dashboard, content, questions and users inline and the rest in an «المزيد» menu at the end of the nav (white, hairline border, shadow-1, items 44 px, closes on Esc or outside click). Login, sign-up, accept-invite, onboarding and the landing page show the same app bar with the logo only. Sub-tabs and filters are pills: 44 px, label 14 px 700, inactive white with the steel `--border-strong`, active `--accent-soft` fill with `--accent` border and `--accent-text`.

**Inputs.** White, `--r-sm` (5 px), steel `--border-strong`, 44 px height, 9 px by 12 px padding, 16 px. Labels 14 px `--text-2` above the field with 6 px gap. Selects in filter rows may be 36 px. Every select has its native arrow removed and a 16 px chevron-down in `--text-2` at inline-end (40 px padding), in both directions. A group of choices is a fieldset whose legend is an ordinary label inside the group (16 px 700 in a card, 14 px `--text-2` in a form), never drawn on the group's border.

**Tables.** Inside a card, no vertical rules, hairline row separators, header 14 px 700 `--text-2`, cells 14 px with 9 px by 10 px padding, right aligned. Sticky header on desktop. Horizontal scroll inside the card on mobile. Row actions are 36 px `sm` buttons. Activity dates (session history, student history, assistant conversations, audit log) read «قبل ساعتين» within a day, with the full date on hover. Admin data views exception: DESIGN.md says "no dense data tables", but admin and teacher tables, KPI tiles and charts (and the student's history and progress tables) stay dense, restyled only through the tokens.

**Cards in a grid.** Subject cards and plan cards: grid with `minmax(280px, 1fr)` on 700 px and up, single column below. Dashboard KPI tiles: 2 columns, 4 from 700 px; dashboard panels and charts: 1 / 2 / 3 columns.

**Assistant panel** (AI Avatar). Floating pill button bottom-start: white, 2 px `--accent` outline, `--accent-text` 14 px 700 label, shadow-1, 48 px (hover `--accent-soft`). Opens a slide-in sheet from the start edge, max 380 px, full height, white, shadow-1, rounded outer corners `--r-lg` (16 px). Student bubbles `--soft` with no border; assistant bubbles white with hairline border; a 14 px sparkle icon in `--accent-text` marks the assistant. 220 ms slide.

**Dialogs.** Centred, max 420 px, `--r-lg` (16 px), 20 px padding, shadow-1, overlay `rgba(37,43,47,.40)` above the app bar and tab bar.

**Hero banner.** A contained banner (not full-bleed) on `--hero`, inside the page container: `--r-lg` 16 px, padding 20 px (32 px from 900 px), white text, a Display 800 headline, body copy at most 480 px wide, an optional mint primary, and a decorative white 10 % halo circle at the bottom-end corner from 900 px. No shadow. Only on the landing hero, the student home headline (also reused as the student progress summary) and the subscribe header. In RTL the gradient mirrors (deep indigo at inline-start).

**Circle tiles.** A 56 px mist (`--bg`) circle holding the subject's initial (18 / 24 px 800 in `--accent-text`; a leading «ال» is dropped) on home subject cards, or a value icon on the landing page; a 44 px circle (14 px 700) holds each unit's number on the subject page. Decorative (`aria-hidden`); the name stays the label.

**Sticky exam header.** White card, `--r-md`, shadow-1, sticks under the app bar, holds the countdown in 18 px 800, turning `--bad` in the last two minutes.

### 2.5 Motion and icons

- 150 ms for hover and focus, 220 ms for panels and dialogs, 400 ms for progress bar fill. Easing `cubic-bezier(.2,.8,.2,1)`. Honour `prefers-reduced-motion`.
- Correct answer: feedback panel fades in, option border transitions. No confetti, no bounces.
- Icons: Lucide, stroke 1.8, round caps. 22 px in navigation, 16 px inline. Inline SVG. No emoji anywhere.

## 5. Business rules that must survive the redesign

These are implemented in `prototype/app.js` (`window.ElmanhgTest` exposes the grader, servable check, quiz selector and blueprint merge for you to reuse or verify against). Keep them identical:

1. Servable question = approved AND lesson published AND not retired. Derived, never stored.
2. Content edit on an approved question → pending, version + 1, revision kept.
3. Only a teacher assigned to the subject can approve or reject. Reject needs a reason. Admin has no approve button.
4. Quiz selection order: unseen → last wrong → correct once → rest by least recent. Random within bucket. No repeats in a session.
5. Mastery = normalised score ≥ 0.8 on the two most recent attempts. Every attempt is stored.
6. Headline counter = platform servable total − student's mastered count.
7. Exams come from blueprints; shortfall shows a clear message; multi-unit merges blueprints proportionally.
8. Exam retakes unlimited; best score shown; all attempts listed.
9. Assistant never reveals answers during an in-progress exam.
10. Ask a Teacher: 24 h SLA with red "متأخر" badge on breach, one follow-up, voice always has a transcript, rating on close.
11. Plan changes only via the simulated Paymob webhook modal or an admin refund.
12. Every content change, validation decision, publish, grant and export is written to the audit log.
13. Arabic answer normalisation: strip tashkeel and tatweel, unify أإآ→ا, ة→ه, ى→ي, Arabic-Indic digits → ASCII, trim and collapse whitespace; each rule can be switched off per question.
14. A deleted assistant chat is gone everywhere (student history, admin view); deleting a chat never restores today's messages.
