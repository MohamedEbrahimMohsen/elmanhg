# Plan — Runtime settings, feature flags and admin Configuration page (#253, E18.S1)

## Goal
An admin opens `#/admin/configuration` (nav «الإعدادات») and sees everything configurable in one page. Business settings and feature flags (Ask a Teacher reply time and reminder hours, plan limits, AI review thresholds, Ask a Teacher upload limits, the unit-exam lesson-open gate) can be changed or reset to their deployment default at runtime, take effect without a restart, are validated against a typed definition and are audit-logged with the old and new value. A read-only section shows the environment, the provider of each integration (fake, local or real), the AI service models, safety switches (`Payments:AllowFakePayments`) and whether each secret is set, never its value. #254, #255 and #256 then register their own settings through the same small API.

## Scope
**In:**
- `RuntimeSettingOverrides` table plus migration; a typed registry (`IRuntimeSettingDefinitions` per group, `RuntimeSettingRegistry`); the cached typed accessor `IRuntimeSettings`; startup validation of every default.
- 14 seeded settings in 5 groups (table in Decisions D8). Every existing reader of those options switches to `IRuntimeSettings`.
- Admin API: list by group, update one, reset one, read-only infrastructure. Policy `Configuration.Manage`, Admin only. Update and reset are audited (`IAuditableCommand` plus an `IAuditedEntity` diff).
- AI service `GET /v1/configuration`: providers, models, and API-key set/not set. The .NET typed client for it.
- Web: the Configuration page in ar/en (RTL), lazy-loaded with its own locale bundle; an editor per setting type; client and server validation errors; reset; the infrastructure section; the nav item and capability.
- OpenAPI, Orval, route tree, Postman, `appsettings.example.json`.
- Docs: new `docs/configuration.md`; PRD §3.3, §6.1, §7.4, §9.3, new §10.6, §11.1, §12.1, §16, §17; `docs/implementation-report.md` §4; `docs/backlog.json` epic E18; audit-log, ask-teacher, subscriptions, essay-grading, math-step-grading, grade-review, exams, sessions, security, deployment, ai-service; claude-design-prompt §4; prototype.md.

**Out:**
- Runtime editing of prices, currency, grace period, renewal window, mastery threshold, rate limits, sweeps, text caps and page sizes (D8 says why for each).
- SLA calendar and exam periods (#254), the out-of-app teacher reminder (#255), the refunds flag and the `AllowFakePayments` default change (#256).
- A cross-instance cache invalidation broadcast. The 30 s TTL bounds staleness (D2).

**Deferred:** none. Nothing here needs credentials or an external service.

## Decisions
| # | Question | Decision | Why |
|---|----------|----------|-----|
| D1 | Storage shape | One `RuntimeSettingOverride` row per key that has ever been overridden: `Key` (unique, varchar 100) and `Value` (jsonb, **nullable**: null means "use the default"), plus an xmin `Version`. The first override inserts the row. Reset sets `Value` to null and never deletes the row. | The audit diff then always shows the before and after value (`Modified`, value → null). No soft-delete row collides with the unique key. A null value can never be mistaken for a configured default. |
| D2 | Cache and invalidation | `CachedRuntimeSettings` caches the computed `RuntimeSettingValues` (every key → effective JSON value) in `IMemoryCache` under `runtime-settings:values`, with TTL `RuntimeSettings:CacheSeconds` (default 30, range 1–3600). The update and reset handlers call `memoryCache.Remove` after `SaveChangesAsync`. | Mirrors the existing `IMemoryCache` plus `Remove` pattern (`CheckUserActive`, `ServableQuestionCountInvalidation`). Hosting is a single VPS instance (#112); on a second instance the TTL bounds staleness at 30 s. One indexed query per TTL. |
| D3 | How a story adds a setting | 1) Declare `public static readonly RuntimeSettingKey<T> X = new("group.name");` in a group class implementing `IRuntimeSettingDefinitions`. 2) Add a `RuntimeSettingDefinition.ForInteger/ForDecimal/ForBoolean/ForChoice/ForChoiceList(...)` entry whose default reads the existing `IOptions<TOptions>` value. 3) For a new group class, add an enum member to `RuntimeSettingGroup` and register it with `services.AddSingleton<IRuntimeSettingDefinitions, XRuntimeSettings>()`. 4) Read it with `await runtimeSettings.GetAsync(XRuntimeSettings.X, cancellationToken)`, or `GetValuesAsync` for several keys. 5) Add a cross-setting rule, if any, to the group's `Constraints`. 6) Add web `groups.<Group>` i18n for a new group. | This is the whole API. No plugin system: DI collects the group classes. Defaults keep coming from the validated Options, so behaviour is unchanged until an override exists. |
| D4 | Where labels and descriptions live | In the definition, as `LocalizedText Label` and `LocalizedText Description`. The API returns both languages (`labelArabic`, `labelEnglish`, ...); the web picks one by `i18n.language`. | The story requires the description in the typed definition. The admin-facing result exposes both languages (skill §4.5). `LocalizedText` refuses empty text, so a missing translation fails at construction. |
| D5 | Value transport type | `System.Text.Json.JsonElement` in the request and the result (`value`, `defaultValue`); a jsonb string in the DB. Integer → JSON number, Decimal → number, Boolean → true/false, Choice → string, ChoiceList → array of strings. | Natural JSON, one column for every type, and the audit diff shows the raw value. Orval types it `unknown`; the web narrows it per `type` in `readSettingValue`. |
| D6 | Validation layering | The validator rejects a blank key (`RUNTIME_SETTING_KEY_REQUIRED`) and a value that does not satisfy its definition's type, range or allowed values (`RUNTIME_SETTING_VALUE_INVALID`, 422). An unknown key passes the validator; the handler returns 404 `RUNTIME_SETTING_NOT_FOUND`. A broken cross-setting constraint returns 400 (`BusinessRuleViolationCoreException` with the constraint's code). | Value rules depend only on the singleton registry, so they fit the validator. Constraints depend on the stored values of other keys, so they belong in the handler. |
| D7 | Resetting a key that is not overridden | Idempotent 200 with the current state: no write, no cache clear, no constraint check. The audit row has outcome Success and no diff. | The UI only offers Reset when `isOverridden`; a double click must not error. |
| D8 | Seed selection | **In** (runtime): **Features**: `features.examsRequireAllLessonsOpened` (`Exams:RequireAllLessonsOpened`, a product gate already treated as a flag, #85). **AskTeacher**: `askTeacher.replySlaHours` (`Subscriptions:AskTeacherReplySlaHours`), `askTeacher.firstReminderAfterHours` and `askTeacher.secondReminderAfterHours` (`AskTeacher:*`): business timing named by the story. **PlanLimits**: `plans.freeDailyQuizQuestions`, `plans.freeDailyAvatarMessages`, `plans.freeOpenLessonsPerUnit`, `plans.baseDailyAvatarMessages`, `plans.askTeacherMonthlyQuestions` (`Subscriptions:*`): quotas read per request, with no stored state. **Grading**: `grading.essayReviewConfidenceThreshold` and `grading.mathStepReviewConfidenceThreshold` (`EssayGrading:` / `MathStepGrading:ReviewConfidenceThreshold`): they only route new grades. **Uploads**: `uploads.askTeacherImageMaxSizeInMb`, `uploads.voiceReplyMaxSizeInMb`, `uploads.voiceReplyMaxDurationSeconds` (`AskTeacher:*`): user-facing limits checked per request. **Out**: `Mastery:CorrectThreshold`, because `QuestionMastery.Mastered` is materialised at attempt time and a change would make stored mastery disagree with selection (PRD §17 rule 6). Prices, `Currency`, `GracePeriodDays`, `RenewalWindowDays`: they move money or access, and in-flight checkouts carry amounts. `Sessions` quiz sizes: the UI picker is fixed at 5/10/20 (prototype). Every `*SweepEnabled`, interval, batch and retry option, and the rate limits: read once by hosted services and rate-limit policies at startup. Text and field max lengths, page sizes and cache seconds: schema and contract caps tied to column widths and AI-service limits. `Content:LessonImageMaxSizeInMb` and `QuestionImportMaxFileSizeInMb`: admin authoring caps, and the import parse-time bound (#153). `AskTeacher:TranscriptionLanguage`: part of the AI-service contract. All infrastructure: the read-only section. | Story: "safe to change at runtime". The selection is restated in `docs/configuration.md`. |
| D9 | Upload maxima | `uploads.*MaxSizeInMb` range 1–9 (const `MaxUploadMegabytes = 9`, with a WHY comment: Kestrel's `MaxRequestBodySize` is 10 MB and multipart overhead must fit under it). Voice duration range 10–600. | An admin cannot raise a cap above what the transport accepts. |
| D10 | SLA change on open threads | `replySlaHours` applies to threads submitted, and follow-ups opened, after the change; the stored `SlaDueAt` of an open thread is not recomputed. Reminder stages of open threads are computed from the stored `SlaDueAt` minus the current SLA (the existing `DueSlaStages`), so changing the SLA mid-window shifts their reminder times. This is documented in `docs/ask-teacher.md` and `docs/configuration.md`; #254 replaces it with recomputed calendar deadlines. | Smallest correct change today; #254 owns deadline recomputation. |
| D11 | Cross-setting rule | AskTeacher constraint `ASK_TEACHER_REMINDER_ORDER_INVALID`: first reminder < second reminder < reply SLA. It is checked on update and on reset against the candidate values. `AskTeacherOptionsValidator` (startup) stays as it is. | Same invariant as the existing startup validator. |
| D12 | Startup safety of defaults | New `RuntimeSettingsOptionsValidator : IValidateOptions<RuntimeSettingsOptions>` runs `RuntimeSettingRegistry.FindProblems` (duplicate keys; a default outside its own definition) and is registered with `ValidateOnStart`. | A deployment value outside the runtime range (for example `AskTeacher__ImageMaxSizeInMb=12`) stops the boot instead of failing on the first request. Mirrors `AskTeacherOptionsValidator`. |
| D13 | Infrastructure reader placement | Application port `IInfrastructureConfigurationReader`, implemented in `Elmanhg.Infrastructure/Hosting/InfrastructureConfigurationReader.cs`. Only Infrastructure sees `OtpDeliveryOptions`, `PaymentsOptions`, `FileStorageOptions` and `AiServiceOptions`. | Layering: Application cannot reference Infrastructure options. |
| D14 | Secret status | The secret key list moves from `PlaceholderSecretGuard.SecretKeys` to `Elmanhg.Infrastructure.Hosting.ConfigurationSecrets.Keys`; `PlaceholderSecretGuard` keeps `SecretKeys` as an alias, so its tests do not change. Set = not blank and not a `change-me` placeholder. Only `{ key, isSet }` is returned. AI-service keys come from the AI service as `{ key, isSet }` too. | One list of secrets. A placeholder is not a usable secret. Values never leave the process. |
| D15 | AI models | New AI-service endpoint `GET /v1/configuration` (service-token auth) returning providers, models and key status. The API calls it only when `AiService:Provider=Http`. Fake gives `aiServiceStatus: NotUsed`; a failed call is logged as a Warning and gives `Unreachable`, and the page still renders. | The models live only in the AI service's env (`ai.env`). #257 will change the values, not the shape. |
| D16 | `AllowFakePayments` slot | Shown now under `safetySwitches` as `{ key: "Payments:AllowFakePayments", isOn }` from the existing `PaymentsOptions.AllowFakePayments`. Never editable; no setting definition. #256 changes only its default and startup rule. | The story says safety switches are read-only. The option already exists. |
| D17 | Types built now | `Integer`, `Decimal`, `Boolean`, `Choice`, `ChoiceList` with parser rules and web editors. `Choice`/`ChoiceList` have no seeded setting; they are covered by tests with test-local definitions. No free `Text` type. | #255 needs Choice (trigger stage) and ChoiceList (channels); #254 needs ChoiceList (weekend days) and Choice (time zone). A future type is added to `RuntimeSettingType`, `RuntimeSettingValueRules`, `runtimeSettingSchemas.ts` and one editor. |
| D18 | Complex values (#254 exam periods) | They are not runtime settings. They get their own aggregate, table and audited CRUD commands under `/api/configuration/<resource>` with the `Configuration.Manage` policy, and a section component that `ConfigurationPage` renders directly under the card of the related group (for example `<ExamPeriodsSection />` after the `SlaCalendar` group card). This story ships no empty extension point. | No speculative code. The contract is written in `docs/configuration.md` §5. |
| D19 | Policy | `DefaultCodes.ConfigurationManage = "Configuration.Manage"`, Admin only. Web capability `configurationManage`. | Every endpoint needs a named policy; the PRD §16 row is added. |
| D20 | Audit | `UpdateRuntimeSettingCommand` (`RuntimeSetting.Update`) and `ResetRuntimeSettingCommand` (`RuntimeSetting.Reset`), resource type `RuntimeSetting`, resource id taken from the result (`IAuditableResult`, `[property: JsonIgnore] Guid? OverrideId`). The entity is `IAuditedEntity`, so the diff shows `key` and `value` before and after. `GetInfrastructureConfiguration` is a read and is not audited. | `docs/audit-log.md` pattern; precedent `AuthResult` for `[property: JsonIgnore]`. |
| D21 | Validators that read upload limits | `CreateTeacherThreadValidator` and `RecordVoiceDraftValidator` inject `IRuntimeSettings` and use `MustAsync`. The pipeline already calls `ValidateAsync`. Their tests switch to `ValidateAsync` (listed as modify). | FluentValidation cannot build a rule from an awaited value in a constructor. |
| D22 | Page order and nav | Groups render in `RuntimeSettingGroup` order: Features, AskTeacher, PlanLimits, Grading, Uploads; then the Infrastructure card. The nav item is the last admin item (`Settings` icon), so it falls under «المزيد» on mobile. | Feature flags are the headline. The tab bar stays at 3 + More (#135). |
| D23 | Integration test isolation | Runtime settings are global state, so the endpoint tests run in `[Collection(RuntimeSettingsCollection.Name)]` with `DisableParallelization = true`. Each test class deletes the rows of registered keys and removes the cache key in `InitializeAsync` and `DisposeAsync`. | Precedent `ServableCountCollection`. Parallel suites never see a changed limit. |
| D24 | `GetInfrastructureConfigurationHandler` unit test | None. The handler only returns `reader.ReadAsync`, and a unit test would assert that a mock returned its value. Covered by `InfrastructureConfigurationReaderTests` plus the integration tests. | Testing convention ("never assert a mock returns what it was told"). |

## Domain behaviour
```csharp
public static RuntimeSettingOverride Create(string key, string value, Guid createdBy)
{
    return new RuntimeSettingOverride(Guid.NewGuid(), createdBy) { Key = key, Value = value };
}

public void Override(string value, Guid updatedBy)
{
    Value = value;
    UpdatedBy = updatedBy;
    UpdationDate = DateTimeOffset.UtcNow;
}

public void Reset(Guid updatedBy)
{
    Value = null;
    UpdatedBy = updatedBy;
    UpdationDate = DateTimeOffset.UtcNow;
}
```
There is no domain guard: validity depends on the registry (Application), and reset is idempotent by D7. The entity is never soft-deleted, but it is still added to the global soft-delete filter (rule §6.4).
