## Notes for review
- Per Decision 7, `json_schema` mode sends the system prompt unchanged. The JSON instruction is added only in `json_object` mode.
- `api_key_for` re-checks for blank keys, because `model_copy` (used in tests and the eval harness) skips validators.
- In `_payload`, the history messages are added with `messages.extend(...)` instead of a starred generator inside the list literal. mypy rejected the inferred `dict[str, str]` against `JsonValue`. The behaviour is the same.
- `deploy/ai.env.example` gets one extra comment line, `# Set ELMANHG_AI_LLM_PROVIDER=openai_compatible to go live.`, above the uncommented `ELMANHG_AI_LLM_PROVIDER=fake`. I did not put an inline comment on the uncommented line, because compose `env_file` parsing of inline comments differs between versions.
- `docs/deployment.md` merges `LLM_STRUCTURED_OUTPUT`/`_MAX_TOKENS_FIELD`/`_REASONING_EFFORT` into one row with the DeepSeek values. The plan listed the four LLM rows without that detail.
- The essay and math step docs use a markdown link `[ai-service.md](ai-service.md)` where the plan text says `docs/ai-service.md`. The prototype doc uses the plain text.
- The deletions were staged with `git rm`. Nothing was committed.
- D-1 (live run and the three live evals) and D-2 (confirm the `gpt-5.6-luna` id and prices) remain deferred. There is no key in this environment.
