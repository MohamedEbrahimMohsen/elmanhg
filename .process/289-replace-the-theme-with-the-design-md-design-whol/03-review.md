**Rule:** the story rule "mint is the only filled chromatic action, one per screen"; `.claude/design-system.md` rule 1 and the Button row ("one mint per screen"); the plan's Layout audit §4 `primary-count` fix rule.
**Problem:** `SubmitButton` defaults to `primary`, so every filter "Apply" is mint. Two kinds of screen get a second mint. The layout audit only visited the default Users tab (Students, where there is no Invite button) and the demo's unfiltered lists, so its `primary` check never saw these states. The report's claim of "at most one mint button on every audited page" holds only for the states that were audited.
**Failure:** on `/admin/users`, open the Teachers tab: «دعوة معلم» and «تطبيق» are both `rgb(17, 238, 146)`. On `/admin/audit`, `/admin/payments`, `/admin/questions`, `/admin/avatar-conversations` or the teacher validation queue, apply a filter that matches nothing: "Apply" and "Clear filters" are both mint. In the validation queue, once a question has been opened in the session, "Apply" and bulk approve are both mint.
**Fix:** apply the audit fix rule. Make each filter form's Apply `SubmitButton variant="secondary"`, as already done in `BlueprintEditor`. That leaves Invite, Clear filters and bulk approve as the single mint on their screens. Then re-run the `primary` check on the Users Teachers tab and on one filtered "no results" list.

### 3. The tailwind-merge fix (Deviation 3) has no regression test, although a test file for exactly this exists
**Where:** `web/src/shared/lib/utils.ts:17` (the `label` entry added to the `text` theme list). There is no matching case in `web/src/shared/lib/utils.test.ts`.
**Rule:** reviewer brief, "a missing test" for a behaviour change. `utils.test.ts` already holds `keeps a font-size token next to a colour token` for `text-ui`, which is the guard pattern for this exact bug class.
**Problem:** the implementer found a real app-wide bug: `cn()` treated `text-label` as a colour and dropped it next to `text-text` and `text-accent-text`, so every Button, pill tab and nav item rendered at 16 px. The fix is correct, but nothing would catch a regression. `button.test.tsx` checks only background fills.
**Failure:** remove the `label` entry from the `text` list in `utils.ts`. All 1814 tests still pass, while every button goes back to 16 px.
**Fix:** add a case to `utils.test.ts` asserting that `cn` keeps `text-label` next to `text-accent-text` (both classes survive). A `shadow-1` merge case would also be worth adding, now that the shadow scale is just `1`.
