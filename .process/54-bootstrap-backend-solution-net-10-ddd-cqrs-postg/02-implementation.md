## Build & test
Commands were run from `D:\Personal\elmanhg` with SDK 10.0.401 and Docker running.

- `dotnet build api/`: **Build succeeded. 9 Warning(s), 0 Error(s).** All 9 warnings are in vendored `core-libraries` code: CS8602 in `Core.Validation/Extensions/RequiredValidationExtensions.cs`, and CS8618 in `Core.OTP/Entities/OTP.cs`, `Core.Notifications/Entities/Notification.cs` and `NotificationTemplate.cs`. There are zero warnings in `Elmanhg.*`, which build with `TreatWarningsAsErrors=true`.
- `dotnet tool restore`, then `dotnet ef migrations add InitialCreate --project api/Elmanhg.Infrastructure --startup-project api/Elmanhg.Api --output-dir Migrations`: `Done.` Inspection of the generated migration:
  - `Notifications.Data` is `type: "jsonb"`.
  - There is no `nvarchar` and no `datetime2`.
  - Every `DateTimeOffset` column is `timestamp with time zone`.
  - `DropTable` appears only in `Down()`.
  - It creates 12 tables: 7 Identity tables plus AuditLogs, Notifications, NotificationTemplates, Otps and UserDevices.
- `dotnet test api/`: **Test run summary: Passed! total: 14, failed: 0, succeeded: 14, skipped: 0, duration: 1m 12s 599ms.** The duration includes the first pull of the `pgvector/pgvector:pg17` image.
- `dotnet list api/ package --vulnerable --include-transitive`: all 20 projects reported "has no vulnerable packages given the current sources".
- `dotnet ef migrations has-pending-model-changes --project api/Elmanhg.Infrastructure --startup-project api/Elmanhg.Api`: "No changes have been made to the model since the last migration."
- DoD greps: `grep -rniE "SqlServer|MSSql|UseSqlServer"` found nothing in source/props/json/slnx, `grep -rn "DateTimeOffset.Now"` found nothing, and `NoWarn`/`UserSecretsId` appear nowhere in `api/`.
- Local run:
  - Port 5432 on this machine is taken by another project's container (`zeema-db-1`), so I made a temporary `.env` from `.env.example` with `POSTGRES_PORT=55432` and a matching connection-string port.
  - `docker compose up -d postgres` reached `healthy`, and `dotnet ef database update` applied `20260927195417_InitialCreate`.
  - After `dotnet run --project api/Elmanhg.Api --launch-profile http`, `curl http://localhost:5080/health` returned `Healthy`, and `/scalar/v1` and `/openapi/v1.json` returned 200.
  - Afterwards I stopped the app, ran `docker compose down -v`, and deleted the temporary `.env`.

## Notes for review
- **Instruction paths.** The testing convention is at `.claude/conventions/dotnet-testing.md`, not `conventions/dotnet-testing.md`. The implementer instructions name `postman/e3a.postman_collection.json`, but the plan and SKILL §9 both say `postman/elmanhg.postman_collection.json`. I followed the plan.
- **Program.cs.** It is exactly the plan's G2, including its three WHY comments. The top-level `await app.RunAsync()` and `await Serilog.Log.CloseAndFlushAsync()` have no `.ConfigureAwait(false)`, because the plan's verbatim text doesn't have it.
- **EF value-comparer warning.** `dotnet ef` logs `The property 'Notification.Data' is a collection ... with no value comparer` for vendored `CoreDbContext`. Morabh hid it with `CoreEventId.CollectionWithoutComparer` in `OnConfiguring`, but F3 forbids `OnConfiguring`. It is a runtime log warning, not a build warning. There is also the expected MediatR licence-key warning (licence config is Deferred).
- **Test namespace.** Test files under `Elmanhg.Tests.Core.Exceptions` create an `Elmanhg.Tests.Core` namespace. The top-level `using Core.*` directives still resolve to the global `Core`. A later test that writes a qualified `Core.X` inside the `Elmanhg.Tests` namespace would need `global::`.
- **Unit-test helpers.** `CoreExceptionMiddlewareTests.ReadBodyAsync` is a private helper outside a test method body, so it uses `.ConfigureAwait(false)`. The localizer substitute returns argument index 1 (the fallback message) `?? string.Empty`, as the plan says.
- **T9.** It uses FluentAssertions `ContainItemsAssignableTo<ValidationBehaviour<PipelineProbeRequest, Unit>>()`.
- **Test config reaches the host.** `ApiFactory` config injection works: the lazy connection-string read inside `AddDbContext` sees the in-memory override, as D15 predicted.
- **`.process/` is untracked.** The orchestrator decides what gets committed.
- **Docs-sync.** The constitution already describes `.env`/`.env.example`, gitignored `appsettings.json`, Npgsql and xUnit + NSubstitute + FluentAssertions, so it agrees with this change. No `/docs` divergence found.
