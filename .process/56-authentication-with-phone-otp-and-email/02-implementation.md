## Notes for review
- `AddCoreOtp` calls `AddValidatorsFromAssemblyContaining` twice on the same assembly. That registers the OTP validators twice, so a 422 `code` can repeat a value (for example `X,X`). This is pre-existing Core behaviour. The tests use "contains".
- `FakeSmsSender` logs the OTP at Information outside Production, as the plan requires. That is the only place a secret is logged.
- The local, gitignored `api/Elmanhg.Api/appsettings.json` was not changed. For a local `dotnet run`, the dev must copy the new sections from `appsettings.example.json` into it; otherwise `ValidateOnStart` fails. Tests do not need this.
- `PhoneStartForm` types its schema as `z.ZodType<PhoneStartValues, PhoneStartValues>` so it can switch between the sign-in and sign-up schemas without a cast.
- OTP entity tests live under `Tests/Core/Otp`. In that namespace, `Otp` resolves to the namespace itself, so the tests use the alias `OtpEntity` or `global::Core.OTP.Entities.Otp`.
- Postman and `.env` only use the placeholder values from `.env.example`. No real secrets are anywhere.
- Program.cs (113 lines) and some test classes (up to 192 lines for LoginPage.test.tsx) are over ~100 lines. All new production files are ≤ 97 lines.
