# Plan — [E11.S2] Dashboard UI (#105)

## Goal
An admin opens `/admin` and sees the PRD §10.3 dashboard instead of the placeholder: nine KPI cards (students, subscribers, content, solve rate, success rate, validation, Ask a Teacher, payments, sign-up funnel), three daily bar charts (attempts, revenue, validation decisions), and a success-rate table by subject / unit / lesson. A filter row (subject, and a 7 / 14 / 30-day period) drives all of it and is kept in the URL. Every number comes from the nine `GET /api/dashboard/*` reads shipped in #104 (`docs/dashboard.md`), through the generated Orval hooks.

## Scope
**In:** web only. New feature `web/src/features/dashboard/` (sub-tasks: KPI card components; time-series charts for attempts, revenue and validation throughput; filter bar with period and subject). The `/admin/` route is wired. Test fixtures and default MSW handlers. A bundle budget for the admin dashboard page. Doc sync (`docs/claude-design-prompt.md` §4, `docs/performance.md` §3–§4, `docs/dashboard.md` Filters).
**Out:** API changes (none needed; #104 is merged and the Orval client is current). The teacher personal stats page (#107). A free-form date picker (the design prompt fixes the period to 7 / 14 / 30 days). CSV export. Auto-refresh.
**Deferred:** nothing.

Morabh reuse: none. Morabh (`D:\Personal\Projects\Projects\Morabh\repos\apis`) is API-only and has no frontend. Every file below is new, with no Morabh equivalent.

## Decisions
| # | Question | Decision | Why |
|---|----------|----------|-----|
| D1 | Chart library? | **No third-party library.** One hand-written SVG component, `DailyBarChart` (about 2 KB). No new dependency, so nothing needs lazy-loading. It lives only in the auto-split `/admin/` route chunk. | Only three single-series daily bar charts are needed, and the prototype itself draws them as plain SVG (`svgBars` in `prototype/app.js`). Alternatives checked (`npm view`, 2026-09-30): **recharts 3.10.1** (MIT) pulls in `@reduxjs/toolkit`, `react-redux`, `immer` and `victory-vendor` (d3), tens of KB brotli for three bar series. **chart.js 4.5.1** and **uPlot 1.6.32** (MIT) draw on canvas: no DOM for screen readers, nothing to assert in jsdom, and we would still need our own a11y table. **@visx/shape 4.0.0** (MIT) is modular SVG but adds `@visx/scale`, `@visx/vendor` (d3) for geometry we can write in about 10 lines. If a later story needs richer charts, the choice is @visx (MIT), loaded with `lazy()` inside the admin route chunk. |
| D2 | Period options and default | `7`, `14`, `30` days; default **14**. | `docs/claude-design-prompt.md` §4 says "7 / 14 / 30 days", and the prototype's `DF.days` is 14 ("match behaviour one to one"). |
| D3 | How the period becomes `from`/`to` | The browser computes both, in Cairo days: `to` = today in `Africa/Cairo`, and `from` = `to − (days − 1)`. Both go on every ranged request. | All nine cards share an identical range and cache key. The chart x-axis equals the chosen period exactly. The server's own default (30 days) does not leak in. |
| D4 | Where the filters live | URL search params `?days=7|14|30&subjectId=<uuid>`, validated by `dashboardSearchSchema` (both optional; an invalid value is dropped). | Handbook §4 ("filters live in the URL"). This follows `blueprintsSearchSchema` and `paymentLogSearchSchema`. All-optional keeps `<Link to="/admin">` in `navConfig` valid without `search`. |
| D5 | Subject list for the filter | `useGetSubjects()` (as used by `ExamBlueprintsPage`). While it is pending, or if it fails, the select shows only «كل المواد» and the cards still load. | The filter is optional, so a subjects failure must not blank the dashboard. |
| D6 | Cards with no subject dimension | Students, Subscribers, Payments and Funnel show a note «لا يُفلتر حسب المادة» when a subject is chosen. Content shows «لقطة حالية، لا تُفلتر حسب الفترة» always. The revenue chart shows the subject note too. | PRD §10.3 and `docs/dashboard.md` Filters. The admin must not read an unfiltered number as filtered. |
| D7 | Load and fail granularity | One query per card, and each card has its own skeleton, error and retry. Charts and the breakdown reuse the same query key as their KPI card (TanStack dedupes, one request each). | One slow or failing read must not block the other eight. No request is made twice. |
| D8 | Digits | Every number, date and amount uses `'latin'` digits (`ar-EG-u-nu-latn` in Arabic). | `docs/claude-design-prompt.md` §2: "ASCII digits in admin tables and exports". This matches `payments`, `audit` and `avatarConversations`. |
| D9 | Chart direction in Arabic | The SVG and its axis row are `dir="ltr"`: time runs oldest→newest left→right in both languages. | The prototype sets `direction="ltr"` on its chart SVG. |
| D10 | Chart colour | Bars use `fill-text-muted` and the baseline uses `stroke-border-strong`. | Design-system rule 1: only action, correct, wrong and pending are coloured. The prototype bars are grey. |
| D11 | Chart accessibility | The SVG is `aria-hidden`, and each bar has a `<title>` (hover tooltip). An `sr-only` `<table>` (caption = chart title, columns Date / Value) carries the data. The first and last day and the peak value are visible text under the chart. | WCAG 1.1.1. Tests assert through the table. |
| D12 | Empty states | A chart whose values are all 0, or whose array is empty, shows a one-line empty message instead of the SVG. The breakdown with no rows shows «لا توجد محاولات في هذه الفترة.». KPI cards have no empty state: 0 is a figure. | Handbook §12. The prototype shows zeros on KPI cards. |
| D13 | Questions by type | Shown inside the Content card as a `<ul>` («{type}: {count}»), with type labels from `questions:types.*`. There is no bar chart. | Keeps the chart component to one kind (daily series). The data matches the prototype's third chart. Type labels are already translated in `questions` (reused by `blueprints` and `exam`). |
| D14 | Success-rate breakdown levels | Pill toggle Subjects / Units / Lessons (buttons with `aria-pressed`, default Subjects). Lessons need a chosen subject; without one the card shows «اختر مادة لعرض الدروس.». | Keeps the table under the handbook's 100-row virtualisation limit. There are roughly 400 lessons platform-wide, and one subject has at most tens. |
| D15 | Rates, ratios, durations | Rate: `Intl` percent, max 1 fraction digit. Solve rate: max 2 fraction digits. Duration: seconds < 60 → seconds; < 3600 → rounded minutes; < 86400 → hours (1 dp); else days (1 dp), all `style:'unit', unitDisplay:'long'`. `null` → `—`. | `docs/dashboard.md`: rates are 0–1 or `null`, durations are whole seconds or `null`. |
| D16 | Freshness | A static intro line says figures are in Cairo days and can be up to a minute old. `generatedAt` is not rendered. | Server cache is 60 s (`docs/dashboard.md` Caching). A per-card timestamp adds noise. |
| D17 | Tests reaching `/admin` elsewhere (`AppShell.test.tsx`) | The global MSW server gets default handlers for all nine dashboard reads and `GET /api/subjects` (empty list). | `onUnhandledRequest: 'error'` would otherwise break existing tests that render `/admin`. No existing test is edited. |
| D18 | Bundle budget | Add page `admin-dashboard` to `web/scripts/perf/budgets.json` (entries: `index.html`, `src/routes/admin/route.tsx?tsr-split=component`, `src/routes/admin/index.tsx?tsr-split=component`). `maxKb` = measured × 1.05, rounded up to the next 5. | `docs/performance.md` §3 policy. It guards the dashboard page, and the existing entry, landing, lesson and quiz budgets prove nothing leaked into them. |
| D19 | Headline value per card | Students `total` · Subscribers `activeSubscriptions` · Content `servableTotal` · Solve rate `attemptsPerActiveStudentPerDay` · Success rate `rate` · Validation `pendingBacklog` · Ask a Teacher `openThreads` · Payments `revenue` · Funnel `completedJourneys`. | These match the prototype's `.big` values and PRD §10.3's primary number. |
