# Plan — [E16.S1] Admin diagram authoring tool (#125)

## Goal
An admin can author a **drag-and-drop (diagram) question** in the existing question editor. The admin uploads a raster diagram, which is checked by magic bytes and stored through `IFileStorage`. The admin then draws drop zones on it with the pointer, or adds zones and types their positions from the keyboard, and adds the draggable items. Each item gets its correct zone, or none if it is a distractor. A zone can be marked "order matters", with its items in a set order. The live preview shows the question as the student will see it: the diagram, numbered empty zones and the item bank. It also has a "show correct placements" toggle. The teacher validation page shows the same diagram with the answer key. Everything is stored as a structured JSON model and rendered by React as SVG. No SVG or HTML is ever stored. The stored shape is the contract that #126 (student canvas and per-item grader) grades against. Until #126 ships, drag-and-drop questions are never served to students.

## Scope
**In:**
- `QuestionType.DragDrop`.
- Body and grading-spec schema records, the validation rules, canonicalisation and 7 config caps.
- A diagram image upload endpoint (raster only, magic bytes, public media).
- Drag-and-drop is excluded from servability.
- `grade-draft` refuses drag-and-drop with 422 `QUESTION_TYPE_NOT_GRADABLE`.
- Import ignores a `DragDrop` sheet.
- Web:
  - the image field;
  - the SVG canvas with pointer zone drawing;
  - zone and item editors, correct-zone assignment and zone order;
  - the student preview with the answer-key toggle;
  - the answer-key view on the teacher validation page;
  - type labels.
- Docs, OpenAPI, Orval, Postman.

**Out:** student touch canvas, answer shape, deterministic per-item grader and feedback overlay (#126). Spreadsheet import of diagrams. An interactive drag inside the admin preview (#126 builds the drag interaction; the admin preview is static with the key overlay). Deleting orphaned uploads (same open gap as lesson images, docs/rich-text.md).

**Deferred:** none. Nothing needs credentials or an external service; storage already has the Local and S3 adapters.

| 9 | Answer key shape | The spec is `{"zones":[{"zoneId","itemIds":[…],"ordered":bool}]}`. ## Domain behaviour
- `Question` itself is unchanged. The content is opaque `QuestionContent`, so create, update, resubmit, approve, reject, retire, versioning, revisions, `SubmittedAt`, events, audit and `UpdationDate` all apply to DragDrop exactly as to any other type. A key or geometry change is a content edit: the version bumps and an Approved question returns to Pending.
- `ServableQuestionSpecification.QuestionCondition` excludes `DragDrop`. `IsSatisfiedBy` (compiled) and `WhereServable` (SQL) both pick this up. There is no migration: `Questions.Type` is a string column without a check constraint, and the jsonb columns are schemaless.
- `QuestionGrader.Grade(DragDrop, …)` stays on the existing `_ => throw InvalidOperationException` arm. It is unreachable because drag-and-drop is not served and grade-draft returns 422.

Canonical body (`<URL>` = `QuestionBuilder.DragDropImageUrl`):
```json
{"image":{"url":"<URL>","width":800,"height":600,"alt":"Plant cell"},"zones":[{"id":"z1","x":10,"y":10,"width":20,"height":15,"capacity":2},{"id":"z2","x":50,"y":40,"width":30,"height":20.5,"capacity":2}],"items":[{"id":"i1","text":"Nucleus"},{"id":"i2","text":"Vacuole"},{"id":"i3","text":"Wall"},{"id":"i4","text":"Membrane"},{"id":"i5","text":"Engine"}]}
```

Canonical spec (z1 unordered, sorted by item order; z2 ordered, kept as authored; i5 is a distractor):
```json
{"zones":[{"zoneId":"z1","itemIds":["i1","i2"],"ordered":false},{"zoneId":"z2","itemIds":["i4","i3"],"ordered":true}]}
```
Messy request, used in I1 and A29. The same body has `"alt":"  Plant cell "`, `"text":" Nucleus "`, `"extra":1` at the body root and `"extra":1` on zone z1. The spec is `{"zones":[{"zoneId":"z2","itemIds":["i4","i3"],"ordered":true},{"zoneId":"z1","itemIds":["i2","i1"]}]}`.
