# Plan — [E21.S3] Core quick wins: required user id, paging rules, load-or-404, soft-delete filter, validators, time helpers

## Goal
Promote the small helpers the app repeats in 100+ places into `api/core-libraries` (app-agnostic, every app-specific value passed in) and switch every matching call site to them. After this ships a developer writes `currentUserService.GetRequiredUserId(code)`, `repository.GetRequiredAsync(id, code, ct)`, `RuleFor(x => x).ValidatePaging(...)`, `page.Map(...)`, `query.ToPageDataAsync(...)`, `ValidateDateRange` / `ValidateDistinct` / `ValidateFileSignature`, `AddValidatedOptions<T>()`, `TruncateToMicroseconds()`, `zone.LocalDate()` / `zone.StartOfDay()`, `otpRepository.ConsumeAsync(...)` and `modelBuilder.ApplySoftDeleteQueryFilters()` instead of hand-copying them. App behaviour is unchanged except the one change the story names: all 14 paged endpoints now reject (422, their existing `*_PAGE_NUMBER_INVALID` code) a page number whose row offset passes `int.MaxValue`, which only `GET /api/avatar/my-conversations` did before.

## Scope
**In:** all seven sub-tasks of story 306:
1. `GetRequiredUserId` (Core.Identity) at 109 sites.
2. `ValidatePaging` (Core.Validation) in 14 validators. `PageData<T>.Map` (Core.DDD) at 12 sites. `ToPageDataAsync` (Core.EntityFrameworkCore) in `Repository<T>.FindPaginatedAsync` and the 2 hand-rolled infra repositories.
3. `GetRequiredAsync` (Core.DDD, both id and predicate overloads) at 95 sites.
4. `ApplySoftDeleteQueryFilters` (Core.EntityFrameworkCore) replacing the 42 hand-written filters in `AppDbContext`. `CoreDbContext` is not touched and the EF snapshot does not change.
5. `FileSignature` + `ValidateFileSignature` at 5 validators. `ValidateDateRange` at 6 validators. `ValidateDistinct` at 3 validators. A `Guid?` overload of `ValidateRequired` at 1 validator.
6. `TruncateToMicroseconds` and the `TimeZoneInfo` `LocalDate` / `StartOfDay` helpers (Core.Utilities). `AddValidatedOptions` at 30 registrations. `IOtpRepository.ConsumeAsync` (Core.OTP) in the 4 auth handlers.
7. Tests for every new core helper, 15 added app regression tests, and docs.

**Out:**
- Sites whose shape differs; they are listed in Decisions D17–D22 and are left alone on purpose.
- Changes to `CoreDbContext`, Core.Notifications structure, or any project/NuGet package addition.

## Decisions
| # | Question | Decision | Why |
|---|----------|----------|-----|
| D1 | Where do the core helpers live, and are they interface members or extensions? | Extension methods: `GetRequiredUserId` on `ICurrentUserService`; `GetRequiredAsync` on `IRepository<T>`; `ConsumeAsync` on `IOtpRepository`. `IRepository<T>`, `Repository<T>` and `ICurrentUserService` keep their member lists. | Extensions call the existing interface members (`UserId`, `GetByIdAsync`, `FirstOrDefaultAsync`, `FindByVerificationId`), so every existing NSubstitute test that stubs those members keeps passing unchanged. The rule is "existing tests keep passing", and none may be edited to go green. |
| D2 | `GetRequiredAsync` argument forwarding | It forwards `include`, `orderBy` and `asNoTracking` exactly as passed (same defaults as the base methods), so a stub configured for the old call still matches. | NSubstitute matches on every argument value. |
| D3 | `GetRequiredUserId` semantics | Returns `UserId` when it is non-null and not `Guid.Empty`. Otherwise it throws `UnauthorizedCoreException(errorCode)`. The error code is a required parameter. | This is identical to the 108-copy guard. Core stays app-agnostic, so the app passes `ErrorCodes.UserNotAuthenticated`. |
| D4 | Shape of `ValidatePaging` | `RuleFor(x => x).ValidatePaging(x => x.PageNumber, x => x.PageSize, maxPageSize, pageNumberErrorCode, pageSizeErrorCode)` on `IRuleBuilder<T, T>`, in three `Must`s: page number ≥ 1; `PageCalculator.Offset(n, size) <= int.MaxValue` (skipped when n < 1); 1 ≤ size ≤ max. | A FluentValidation extension cannot call the protected `RuleFor`. One root-level call keeps the story's single `ValidatePaging(...)` name. The order and codes match today's two rules, so existing `Should().Equal(code)` tests still pass. Property names are not asserted anywhere (verified). |
| D5 | Shape of `ToPageDataAsync` | `IQueryable<T>.ToPageDataAsync(int pageNumber, int pageSize, CancellationToken)` on an already-ordered query: `LongCountAsync`, then `PageCalculator` offset and past-end check, then `Skip/Take`. `Repository<T>.FindPaginatedAsync` now applies `orderBy` before calling it. | It is the exact body of today's `FindPaginatedAsync`. EF drops `ORDER BY` from `COUNT`, so the SQL is equivalent. |
| D6 | `PageData<T>.Map` | An instance method `PageData<TOut> Map<TOut>(Func<T, TOut> selector)` that copies the 4 paging fields. | The 12 copies are field-for-field identical (verified: 5/5 lines match in each). |
| D7 | Soft-delete convention scope | `ApplySoftDeleteQueryFilters()` adds `x => !x.IsDeleted` to every entity type whose CLR type implements `ISoftDeletable`, is a root (`BaseType is null`), is not owned, and has no declared query filter yet (`GetDeclaredQueryFilters().Count == 0`). | Root only: EF rejects filters on derived types. "No existing filter" leaves `CoreDbContext`'s 5 filters and any custom filter untouched. |
| D8 | `User` implements `IEntity`, not `ISoftDeletable`, so the convention would miss it | Add `ISoftDeletable` to `User`'s base list. `User` already has `IsDeleted` and `DeletedAt` with identical signatures, so this changes no members, columns or snapshot. | This lets all 42 hand-written lines go, so §8.5 "one home" holds. `ISoftDeletable` is referenced nowhere else (grep), so nothing else changes. |
| D9 | Proof of no model change | `git diff --exit-code -- api/Elmanhg.Infrastructure/Migrations`, plus the existing `AppDbContextTests.Model_Current_MatchesLatestMigrationSnapshot`, plus a new test pinning the filtered set to the exact 47 pre-change types. | Query filters are not in the snapshot, so the set test is what proves equivalence. |
| D10 | `FileSignature` model | `sealed class FileSignature` holds `Extensions` (lower-case) and `Patterns` (`byte?[]`, where null is a wildcard byte; any pattern may match). Built-ins: `Png`, `Jpeg` (.jpg/.jpeg), `WebP` (RIFF????WEBP), `Gif` (GIF87a\|GIF89a), `WebM`, `Ogg`, `Mp4` (.mp4/.m4a, ????ftyp), `Zip` (.zip). `ForExtensions(params string[])` rebinds the patterns, e.g. Zip as .xlsx. Static `Matches(IFormFile, IReadOnlyCollection<FileSignature>)`: candidates are the signatures listing the file's extension; no candidate → false; reads up to the longest candidate pattern; match = header long enough and every non-null byte equal. | This reproduces each of the 4 hand-written checks byte-for-byte: per-extension binding, WebP needs 12 bytes, MP4 needs 8, Zip needs exactly the 4-byte prefix. |
