# Plan — [E21.S10] Core.Hosting, Core.Observability, Core.Cache, Core.Spreadsheets, rate limits, redaction

## Goal
Pure promotion refactor. After this ships, the generic hosting pieces (reverse-proxy forwarded headers, Kestrel limits, migrate-and-exit, placeholder-secret guard, rate-limit partitions + 429 wiring), the OpenTelemetry setup plus per-request metrics, the query caching behaviour, the ClosedXML spreadsheet reader/writer and a configurable text redactor live in app-agnostic `api/core-libraries/Core.*` projects. Elmanhg consumes them and passes in its own names, keys, error codes and patterns. No HTTP route, status code, error code, metric name, cache key, cache TTL, config key or log text changes.

## Scope
**In:** every sub-task of story 313: Core.Hosting · Core.Observability + RequestMetricsBehaviour · Core.Cache caching behaviour, with the dashboards switched · Core.Spreadsheets with its 3 consumers switched · rate-limit partitions + redactor · tests and docs.
**Out:** Core.Notifications and CoreDbContext stay as they are (dev decision 2026-10-06). `LoadTestSeedCommand`, `ConfigurationSecrets`, `TrainingDataScrubber`'s keys and patterns, rate-limit policy names, and `RateLimitingOptions`, `AuthOptions`, `AnalyticsOptions`, `ClientErrorsOptions` and `DashboardOptions` all stay in the app. The middleware order in `Program.cs` does not change, and nothing in `CoreExceptionMiddleware` placement is touched (lane #304 owns that).
**Deferred:** none.
