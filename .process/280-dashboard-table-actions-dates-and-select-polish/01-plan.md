# Plan — [E19.S2] Dashboard, table actions, dates and select polish (#280)

## Goal
After this ships, an admin reads `/admin` as a dataviz dashboard: a row of eight KPI tiles (one number, short label, period delta where the API has one), equal-height panels of aligned label/value rows and horizontal bar breakdowns, and three accent-coloured daily charts with a y scale and every day of the period on the axis. Every button shows the hand cursor (not-allowed when disabled). Table row actions share one compact style (destructive differs only by red text). Every date, time and number in the app uses Latin digits, through one shared formatter, e.g. «3 أكتوبر 2026، 2:37 م». Recent activity reads «قبل ساعتين» with the full date on hover. Every `<select>` is one shared `Select` with a chevron at inline-end in RTL and LTR.

## Scope
**In:** `web/` only. All five sub-tasks:
1. Dashboard redesign.
2. Global cursor and one row-action style.
3. Shared date/time formatter and the Latin-digit policy everywhere, including ICU `{x, number}` and the landing counter.
4. Shared `Select` applied to all 16 selects.
5. Docs: both design-system files, `docs/claude-design-prompt.md` §2.2/§2.4/§4/§6, and `docs/performance.md` only if a budget moves. Also tests and a green `perf:budget`.

**Out:**
- Item 5 of the story (indigo hue on different displays): display calibration, no change.
- API, AI service, prototype.
- `TeacherStatsCard` layout: it keeps `KpiFigure` as is.
- Input normalisation helpers that turn typed Arabic-Indic digits into Latin (`toLatinDigits` in `mathStepsValue.ts`, the ai CAS lexer, `convertDigits`). They enforce the policy and stay.
- `docs/prototype.md`: it does not describe these screens at this level, so no change.

**Deferred:** none.
