# Plan — [E13.S4] Security hardening (#115)

## Goal
After this ships, the platform protects student data and payments better in five ways. Every anonymous endpoint and every costly student action (Avatar, Ask a Teacher) is rate-limited. A student can have only one Avatar or Ask a Teacher request in flight at a time, which makes the daily and monthly quotas exact on the single-instance host (#211). The edge sends HSTS, CSP, anti-framing and related headers, and strips client-sent `CF-*` headers, so log IPs cannot be spoofed. Uploads are checked by file signature, not only by name, and request bodies are capped at 10 MB. Neither the API nor the ai service will start outside Development while an example `change-me` secret is still configured. CI adds a full-history secret scan, a weekly dependency audit and a container-image vulnerability scan. The endpoint authorisation review is recorded in `docs/security.md` and pinned by tests.

## Scope
**In** (the four sub-tasks, plus security items triaged from the follow-up issues):
- Sub-task 1, authorisation review: a reviewed allow-list of anonymous endpoints pinned by a test, the review record in `docs/security.md`, and CORS absence pinned by a test.
- Sub-task 2, rate limits:
  - `auth/refresh` (the only auth endpoint without one), `questions/servable-count` + `plans` (#156) and the Paymob webhook (#191).
  - Avatar messages and Ask a Teacher create/follow-up, per student, plus a per-student concurrency cap (#211).
  - `AddAuthRateLimiting` renamed to `AddAppRateLimiting` (#197).
- Sub-task 3, input sanitisation:
  - Rich text is already sanitised on the server and the client (review only).
  - Lesson image magic-byte check.
  - Question-import `.xlsx` zip-signature check (#153).
  - Kestrel request body cap of 10 MB (#207).
  - Kestrel `Server` header off.
- Sub-task 4, dependency scanning:
  - Existing per-stack audits kept.
  - New `security.yml`: gitleaks full-history secret scan on every PR and push (#132), plus a weekly/dispatch dependency audit of all three stacks.
  - Trivy image scan in `images.yml`.
- Edge:
  - Caddy security headers, SPA CSP, API CSP, `/api` default `Cache-Control: no-store`, `Server` removed.
  - `CF-*` request headers stripped before the API (`docs/deployment.md` §13).
- Secrets (#205, #137):
  - Placeholder/empty-secret boot guard in the API and the ai service.
  - Smoke and load scripts generate throwaway secrets.
  - `deploy.yml` secrets moved to step-level env.
  - `.dockerignore` excludes `api/**/.env*`.
- Cookie default: `AuthOptions.RefreshTokenCookieSecure` defaults to `true` in code (CI-parity rule).
- Docs: new `docs/security.md`, plus sync edits to PRD §14, deployment, avatar, ask-teacher, paymob, question-import, rich-text and ai-service.

**Out** (reviewed, no change needed):
- Audit coverage: every admin mutation is `IAuditableCommand`, and the non-audited set is deliberate and listed in `docs/audit-log.md`.
- Logging redaction: done in #113. Only the `CF-*` spoof is new here.
- SSRF: no outbound URL comes from user input. Every `AddHttpClient` base address is operator config.
- Server-side rich-text sanitiser: `RichTextSanitizer`. Client: DOMPurify in `SafeHtml`.
- Path traversal: `LocalDiskFileStorage.ResolvePath` and `PublicMediaMiddleware.IsPublicKey`.
- DataProtection keys: persisted in a volume.
- Web (`web/`): no source change. CSP is served by Caddy.
- OpenAPI and Postman: no endpoint shape changes, so no regeneration and no Postman edit.

## Decisions
| # | Question | Decision | Why |
|---|---|---|---|
| 1 | Where the new limits live | New `RateLimitingOptions` (section `RateLimiting`) in `Elmanhg.Api.RateLimiting`, registered inside `AddAppRateLimiting`. The existing Auth, Analytics and ClientErrors limits stay where they are. | This is an API-only concern, and it keeps the hot `Application/DependencyInjection.cs` untouched. |
| 2 | Anonymous public reads (`servable-count`, `plans`) | One per-IP fixed-window policy `public-reads` with a shared bucket, default 300/60 s | CGNAT on Egyptian mobile carriers puts many students behind one IP. 300 per minute only stops floods. |
| 3 | `auth/refresh` limit | Its own per-IP policy `auth-refresh`, 60/60 s. It does not reuse `auth-credentials` (10/60 s). | The SPA refreshes on boot and on every 401, in several tabs, so it needs a looser limit than credential guessing. |
| 4 | Paymob webhook limit | Per-IP `payment-webhooks`, 300/60 s | Paymob posts from a few IPs, so the limit must be generous. It still caps unsigned-POST floods that each write an audit row (#191). |
| 5 | Avatar and Ask a Teacher limits | Per student (JWT user-id claim; IP fallback): `avatar-messages` 20/60 s on `POST /api/avatar/messages`; `ask-teacher-submissions` 10/600 s on `POST /api/teacher-threads` and `POST /api/teacher-threads/{id}/follow-ups` | The sub-task names avatar and Ask a Teacher. The existing daily and monthly quotas stay as the business limits. |
| 6 | Concurrency cap (#211) | `RateLimiterOptions.GlobalLimiter`: a per-student `ConcurrencyLimiter` (default 1, queue 0) applied only to endpoints whose `EnableRateLimitingAttribute.PolicyName` is `avatar-messages` or `ask-teacher-submissions`. The partition key is `"{policy}\|{userKey}"`; every other request gets `GetNoLimiter`. A request over the cap gets 429 `TOO_MANY_REQUESTS`. | It stops parallel requests from passing the quota check together. Chaining a fixed window with a concurrency limiter inside one partition (`RateLimiter.CreateChained`) would leak each inner `FixedWindowRateLimiter` timer per student, because the chained limiter does not dispose its inner limiters. The global limiter keeps both limiters partition-managed. |
| 7 | Error on rejection | Existing `OnRejected` throws `RateLimitExceededCoreException(ErrorCodes.TooManyRequests)`, giving 429 `TOO_MANY_REQUESTS`. | The code, the resx entries and the web i18n key already exist. No new error codes. |
| 8 | Test-host limits | `ApiFactory` raises every new permit limit to `100000` through `UseSetting`. The concurrency cap stays at the production value 1. | Parallel tests share one host and the `unknown` IP partition (TestServer has no remote IP). No test sends parallel requests for the same student. |
| 9 | Request body cap | Kestrel `Limits.MaxRequestBodySize = 10 MB` as the named constant `KestrelHardening.MaxRequestBodyBytes`, plus `AddServerHeader = false` | A transport ceiling above the largest business cap (5 MB uploads, about 0.8 MB escaped essay JSON). The validators still enforce the configurable caps. Kept as a constant (an invariant with a WHY comment) rather than an option. Documented. |
| 10 | Lesson image content check | Add `LessonImageFormats.HasMatchingSignature(IFormFile)` (PNG, JPEG, WEBP, GIF87a/GIF89a), appended to the validator's cascade chain after the size check. Error: the existing `LESSON_IMAGE_TYPE_INVALID` (422). | Mirrors `TeacherThreadImageFormats`/`TeacherVoiceFormats`, the per-feature pattern already used. `TeacherThreadImageFormats` is not refactored. |
| 11 | Import zip check (#153) | Add `QuestionImportFile.HasZipSignature(IFormFile)` (`50 4B 03 04`), appended after the size check. Non-zip bytes now return 422 `QUESTION_IMPORT_FILE_TYPE_INVALID` instead of 400 `SPREADSHEET_UNREADABLE`. A zip that is not a workbook still gets `SPREADSHEET_UNREADABLE`. | This rejects junk before ClosedXML. It is an intentional contract change, so `docs/question-import.md` is updated. The existing corrupt-file test keeps its intent by sending `PK\x03\x04` + junk. |
| 12 | Placeholder-secret guard (#205, #137) | `PlaceholderSecretGuard.EnsureReplaced(IConfiguration, IHostEnvironment)` runs right after `builder.Build()` (skipped for build-time OpenAPI) in every environment except Development. It throws `InvalidOperationException` listing the offending keys (never values) when any of the following holds: a listed secret starts with `change-me` (case-insensitive); the connection string contains `Password=change-me`; `CoreOtp:Secret` is empty. | It runs after `Build()` so the `dotnet ef` design-time host, which stops at `Build()` in CI with no config, is unaffected. It runs before `MigrateAndExit`, so a placeholder host also refuses to migrate. The Testing host (ApiFactory) has real test values. Every example placeholder already starts with `change-me`. BCL exception, no new type. |
| 13 | ai service guard | Pydantic `model_validator`: `env == "production"` and `service_token` starts with `change-me` raises `ValueError("service_token still holds the example placeholder")` | Same rule as the API. `ai.env.example` ships `change-me-…`, and compose sets `ELMANHG_AI_ENV=production`. It is appended at the end of `Settings` to keep any conflict with the #123 lane trivial. |
| 14 | Smoke and load stacks | New `replace_example_secrets <api.env> <ai.env>` in `deploy/lib.sh` writes `openssl rand -hex` values for `CoreJwt__Key`, `CoreOtp__Secret`, `TrainingData__StudentIdHashKey`, `AdminSeed__Password` (`<hex32>A1`, digit guaranteed) and one shared `AiService__ServiceToken` = `ELMANHG_AI_SERVICE_TOKEN`. | 16 | Security headers location | At the Caddy edge only (it serves both the SPA and `/api`).
