## Notes for review
- `Attempt.Outcome` is derived from the stored `NormalisedScore` (rounded to 4 dp) via `QuestionGrade.ToOutcome`, while the grader's own outcome uses the raw value. They can only differ for a raw value in [0.99995, 1), which the current graders cannot produce.
- `SubmitAnswerHandler` grades (`revision.Grade`) before `RecordAttempt`, so a replay or a conflicting answer is graded and discarded. Harmless and pure, but it is extra work on the replay path.
- The sub-microsecond `submittedAt` difference (deviation 2) applies to every timestamp the API returns straight after a save, not only sessions. #76 should compare timestamps loosely or not at all.
- `SessionTestData` helpers keep the plan's signatures (no `CancellationToken` parameter) and use `TestContext.Current.CancellationToken` internally, as the existing private test helpers do.
- Domain tests avoid `DateTimeOffset.UtcNow` in assertions (testing convention): test 9 compares with the previous `LastActivityAt`, test 15 with `StartedAt`.
- `QuestionAnswerRules` was moved rather than rewritten; `GradeQuestionDraftValidator` compiles unchanged and the grade-draft tests pass.
- `ScopeKey` is an unbounded `text` column, as planned (`.IsRequired()` only).
- Integration tests that sign in through `SignedInStudentAsync` do not dispose the returned `HttpClient`, because a deconstructed tuple cannot take `using`. That leaks nothing that outlives the test host.
