# Plan — [E13.S3] Performance targets (#114)

## Goal
A student on a 3G-class connection sees a lesson's content in under 2 s on a cold load, and moves between quiz questions in under 300 ms (PRD §14). The team can prove it: a pinned k6 harness load-tests the hot API paths (quiz start/answer/finish, exam start/save/submit, browse, servable-count, avatar with the fake model) against a seeded production-shaped stack, drives a throttled headless browser through the lesson page and a quiz transition, and enforces budgets. A short smoke load runs in CI on every image build. The full load run is a manual workflow. Web bundle budgets are enforced in web-ci. EXPLAIN plans of the hot queries are captured. The known multi-unit exam N+1 (#181) is fixed. A new Prometheus alert fires when a hot route's p95 goes over budget in production.

## Scope
**In:**
- Web critical path:
  - KaTeX and its CSS load on demand, only for HTML that holds math.
  - The avatar panel is lazy.
  - The lesson route loader prefetches the lesson data.
  - Rich-text images get `decoding="async"`, and every image after the first gets `loading="lazy"`.
  - Admin image uploads are downscaled to WebP (max edge 1600 px) in the browser.
- Build-time brotli and gzip precompression, served by Caddy (`precompressed`).
- A Vite manifest plus a bundle-budget CLI, enforced in web-ci.
- HTTP caching:
  - Public media is `immutable`.
  - `servable-count` is `public, max-age=<ServableCountCacheSeconds>`.
- DB:
  - New index `IX_Attempts_StudentId_CreatedAt`, with its migration.
  - A query-plan guard test.
  - `explain.sql` over 11 hot queries, run after every load run.
- #181: one candidate query for a multi-unit exam draw (was one per unit), and `ExamBreakdown.UnitPosition` without `ToList().IndexOf`.
- Load-test tooling:
  - A `--SeedLoadTestAndExit=true` host command (refused in Production).
  - `deploy/load-test.sh`, k6 scripts and a compose override.
  - The CI smoke step, the manual `load-test` workflow and a results artifact.
- Prometheus `ApiHotPathSlow` alert, with promtool tests.
- `docs/performance.md`, plus the docs-sync edits.

**Out:**
- Lighthouse and `@lhci/cli`: the k6 browser module measures the same throttled load in one pinned tool, and reports LCP and FCP.
- Real-user Web Vitals reporting (RUM): not asked for, and no endpoint exists.
- Server-side image transcoding: needs a native imaging library (ImageSharp's licence, or SkiaSharp native assets). Client-side downscaling covers new uploads.
- Removing English locales from the production bundle (~16 KB gz): every feature's `locales.ts` exports `{ ar, en }` in one object, so it touches ~17 feature modules while other lanes are running. Recorded as a lever in `docs/performance.md`.
- `ExamSessionResultLoader`'s per-unit `GetByIdAsync` loop: at most one PK lookup per selected unit; fixing it rewrites the arrange of 4 handler test classes during parallel lanes. Recorded as a follow-up.
- A `GetStudentLesson` projection (it loads full lesson rows of the subject): only if the full run shows `browse_lesson` near budget. Recorded in docs.
- The `servable-count` cold-cache stampede and rate limit (#156): left to #156 / #115.

**Deferred:**
- A CDN in front of Caddy for `/assets/*` and `/api/media/*`: needs the live domain and hosting (#205; no VPS or DNS exists).
- A full-profile run against real staging hardware: there is no staging host yet. The numbers in docs come from the local full run.
