# Plan — Core.Storage: file storage and media serving (E21.S7, story 310)

## Goal
File storage (`IFileStorage`, `StoredFile`, local-disk and S3 providers, options, validator, DI, content types, public URL) and public media serving (`PublicMediaMiddleware`, `PublicMediaFileProvider`) live in a new app-agnostic `Core.Storage` library. The app declares its private media folders (`teacher-threads`, `training-exports`) in one list that drives both serving paths (Local static files and S3 middleware), so the two can no longer drift. Both the public middleware and the app's `TeacherThreadMediaMiddleware` write files through one shared `WriteStoredFileAsync`. Nothing changes for users: same routes, status codes, headers and content types.

## Scope
**In:**
1. Sub-task "Core.Storage abstraction and providers, with tests": new project `api/core-libraries/Core.Storage`, moving `IFileStorage`, `StoredFile`, `FileStorageOptions`, `FileStorageProvider`, `FileStorageOptionsValidator`, `LocalDiskFileStorage` (with its path-traversal guard), `S3FileStorage`, and DI (`AddCoreFileStorage`). `GetPublicUrl` is written once, on `FileStorageOptions`. `StorageContentTypes` replaces `MediaContentTypes` and uses `FileExtensionContentTypeProvider` defaults for the extensions where they match. The tests move into `Elmanhg.Tests/Core/Storage`.
2. Sub-task "Media middleware and file provider with a PrivateFolders option; one list in the app": `PublicMediaMiddleware`, `PublicMediaFileProvider`, `PublicMediaOptions` and `UseCorePublicMedia` move into Core.Storage. The app declares `MediaStorageExtensions.PrivateFolders` once.
3. Sub-task "Shared stored-file writer; teacher media middleware uses it": `StoredFileResponseExtensions.WriteStoredFileAsync(response, file, cacheControl)` plus `SetMediaHeaders`. `TeacherThreadMediaMiddleware` stays in the app and calls the shared writer.
4. Sub-task "Docs": constitution, SKILL.md, security.md, ask-teacher.md, training-data.md, rich-text.md and implementation-report.md.

**Out:** Program.cs (no edit: `app.UseMediaStorage()` keeps its name and position). Core.Notifications and CoreDbContext (dev decision: untouched). Configuration shape (`FileStorage` section, env var names). Content types on the Local static-file path (it keeps the framework default provider, as today). Presigned URLs. Orphan cleanup.
**Deferred:** none.

## API surface
No new endpoints. `GET {FileStorage:PublicBaseUrl}/**` (default `/api/media/**`) behaves as before:
- `teacher-threads/**`: `TeacherThreadMediaMiddleware` (authorised), `Cache-Control: private, no-store`, `nosniff`. Any other spelling of a private folder returns 404.
- `training-exports/**`: 404 on both providers.
- Other keys: Local uses static files plus `PublicMediaFileProvider`; S3 uses `PublicMediaMiddleware`. Both send `Cache-Control: public, max-age=31536000, immutable` and `nosniff`.
